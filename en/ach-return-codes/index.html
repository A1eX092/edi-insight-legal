ACH return codes and their ISO 20022 mappings

When a U.S. ACH payment is returned, the ACH return record carries a reason code such as R01 (Insufficient Funds). If your bank reports the return in a camt.053 statement, you may see AM04 instead. The tables below show the mappings in Nacha's August 2023 camt.053 guide.

The guide covers returns after settlement and notifications of change. A notification of change is not a return: it tells the originator what to correct for future payments. Nacha covers rejections before settlement in a separate pain.002 guide.

Where the reason appears in the file

In a camt.053, the reason for a return sits in the return information of the entry: <RtrInf><Rsn><Cd>. Nacha's guide puts the ISO code there, for example <Cd>AM04</Cd> for R01. Instead of <Cd>, a bank may use <Prtry> to carry a proprietary reason. Separately, <AddtlInf> carries complementary text, such as the addenda information of the ACH return or a date of death.

One ISO code does not always identify one ACH code. For example, R26, R27 and R85 all map to FF02. NARR, AG01 and ED05 also cover several ACH codes. When you see one of them, read <AddtlInf> or ask your bank for the ACH code.

Notifications of change (C codes)

A notification of change does not return the payment. It tells the originator to correct its data for the next payments. In a camt.053, Nacha maps them as follows.

ACH codeNacha name (2023 guide)What to correctISO code
C01Incorrect DFI Account NumberThe account number.AC01
C02Incorrect Routing NumberThe routing number (often after a bank merger).RC01
C03Incorrect Routing Number and Incorrect DFI Account NumberThe routing number and the account number.NARR
C05Incorrect Transaction CodeThe transaction code (checking versus savings).AG03
C06Incorrect DFI Account Number and Incorrect Transaction CodeThe account number and the transaction code.NARR
C07Incorrect Routing Number, Incorrect DFI Account Number, and Incorrect Transaction CodeAll three.NARR
C08Incorrect Receiving DFI IdentificationThe foreign bank identifier (international entries).RC01
C09Incorrect Individual Identification Number / Incorrect Receiver Identification NumberThe receiver's identification number.BE15
C13Addenda Format ErrorThe format of the addenda (the payment went through).NARR
C14Incorrect SEC Code for Outbound International PaymentFuture payments must be sent as international (IAT) entries.NARR

For a notification of change, Nacha maps the corrected ACH data to the first occurrence of <AddtlInf>.

Codes not mapped in Nacha's camt.053 guide

  • R21, R33, R37–R47 and R50–R53: codes specific to certain entry types (company identification for CIE, destroyed checks XCK, check conversion ARC, BOC and POP, government enrollments ENR, re-presented checks RCK). The guide does not map them.
  • R61–R70: dishonored returns. The guide states they must be sent in the Nacha file format to the ACH Network.
  • R71–R77: contested dishonored returns. The guide does not currently support or map them.

A new code in 2028: R90

Effective March 17, 2028, Nacha adds R90 for entries returned because of the receiving bank's sanctions compliance obligations. R16 will then be named Account Frozen and cover frozen accounts only. Nacha's 2023 mapping guide predates R90 and gives no ISO mapping for it.
